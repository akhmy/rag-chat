# rag-chat

Ассистент для вопросов по документам с интерфейсом в Telegram. Документы разбиваются на фрагменты, для них вычисляются эмбеддинги, а при ответе модель получает найденные фрагменты и недавнюю историю разговора.

Проект находится в разработке. Бот Telegram работает через webhook. HTTP API для пользователей, сессий и сообщений отключён. Консольный клиент `cmd/cli` в текущей версии не работает.

## Возможности

- Загрузка PDF размером до 10 MiB через Telegram. Название документа берётся из подписи к файлу или из имени файла, если подписи нет.
- Поиск по документам пользователя через PostgreSQL и pgvector.
- Сохранение пользователей, сессий, ходов разговора и сообщений.
- Контекст из недавних ходов разговора.
- Потоковая генерация с временными черновиками Telegram и форматированием итогового ответа.
- Меню сессий с пагинацией и созданием новой сессии через `/sessions`.
- Автоматическая генерация названий сессий. Сессия может остаться без названия, например после приветствия.

Для эмбеддингов используется `text-embedding-3-small`, для ответов и названий — `gpt-4o-mini`. Модели сейчас заданы в коде.

## Устройство проекта

```text
cmd/server        запуск сервера и обработчиков Telegram
cmd/ingest        консольная утилита загрузки документов
cmd/cli           консольный клиент прежнего HTTP API
internal/usecase  сценарии приложения
internal/domain   доменные типы
internal/postgres адаптеры базы и сгенерированный sqlc-код
internal/openai   эмбеддинги, генерация ответов и названий
internal/extract  извлечение текста из PDF и TXT
internal/telegram обработка обновлений и отправка ответов
internal/http     маршрутизация webhook и код прежнего HTTP API
internal/appctx   значения контекста приложения
db/migrations     миграции PostgreSQL
db/sqlc           SQL-запросы
```

Для обработки PDF серверный образ устанавливает утилиту `pdftotext` из Poppler.

## Конфигурация сервера

Задайте переменные окружения перед запуском сервера. Настройки PostgreSQL и пути к файлам секретов обязательны. Для переменных `SERVER_*` заданы значения по умолчанию.

| Переменная | Назначение |
|---|---|
| `DB_USER`, `DB_NAME`, `DB_HOST`, `DB_PORT` | Подключение к PostgreSQL |
| `DB_PASSWORD_FILE` | Путь к файлу пароля |
| `DB_OPTIONS` | Параметры подключения, например `sslmode=disable` |
| `OPENAI_API_KEY_FILE` | Путь к ключу OpenAI |
| `TELEGRAM_BOT_TOKEN_FILE` | Путь к токену бота |
| `TELEGRAM_WEBHOOK_PATH` | Путь для POST-запросов webhook, по умолчанию `/tg-webhook-283e43903a25` |
| `TELEGRAM_WEBHOOK_SECRET_FILE` | Путь к файлу секрета webhook |
| `SERVER_ADDR` | Адрес HTTP-сервера, по умолчанию `:8080` |
| `SERVER_READ_TIMEOUT` | По умолчанию `5s` |
| `SERVER_READ_HEADER_TIMEOUT` | По умолчанию `5s` |
| `SERVER_WRITE_TIMEOUT` | По умолчанию `5s` |
| `SERVER_IDLE_TIMEOUT` | По умолчанию `5s` |
| `SERVER_SHUTDOWN_TIMEOUT` | Время на остановку HTTP-сервера, по умолчанию `10s` |

## Telegram

Укажите публичный HTTPS-адрес сервера. Путь в URL webhook должен совпадать со значением `TELEGRAM_WEBHOOK_PATH`. Пример ниже использует путь по умолчанию.

Зарегистрируйте webhook методом Telegram Bot API `setWebhook` с таким телом запроса.

```json
{
  "url": "https://bot.example.com/tg-webhook-283e43903a25",
  "secret_token": "YOUR_WEBHOOK_SECRET",
  "allowed_updates": ["message", "callback_query"]
}
```

Токен в URL Telegram API должен принадлежать тому же боту, который настроен в сервере. Значение `secret_token` должно совпадать с содержимым `tg_webhook_secret`. Сервер отказывается запускаться, если секрет пустой. Повторная регистрация нужна при смене URL, секрета или бота.

### Использование бота

1. Отправьте боту PDF с названием в подписи.
2. Дождитесь завершения обработки и задайте конкретный вопрос по содержимому.
3. Продолжите разговор уточняющим вопросом.
4. Откройте `/sessions`, чтобы посмотреть сессии или создать новую.

Сервер подтверждает приём обновлений через webhook. Загрузка документов и генерация ответов выполняются асинхронно.

## Разработка

Используется версия Go из `go.mod` — `1.27.3`. Для локальной обработки PDF установите Poppler с `pdftotext`.

Из корня репозитория:

```bash
go test ./...
go vet ./...
sqlc generate
go run ./cmd/server
```

Для последней команды нужны настроенные переменные окружения и работающая база с применёнными миграциями. `sqlc generate` запускается после изменения SQL или схемы.

## Текущие ограничения

- Для поиска по PDF нужен текстовый слой. Добавьте его с помощью OCR перед загрузкой сканов.
- Сервер хранит очередь обновлений в памяти. При перезапуске часть уже принятых обновлений может потеряться. Параллельные сообщения в одной сессии могут влиять на контекст ответа.
- `cmd/ingest` поддерживает PDF и TXT, но пока передаёт ID владельца `0`. Для загрузки документов используйте Telegram.

## Обновление существующей базы

В первоначальных миграциях менялись порядок создания таблиц и тип идентификаторов сессий. Текущая схема использует UUID. Перед обновлением сделайте резервную копию и проверьте версию миграций и фактическую схему базы. Базе, где уже применены миграции с `BIGINT` для идентификаторов сессий, нужна отдельная миграция перехода на UUID.
